Design research · 2026-08-05

Gate 6 데이터 플랫폼 정보밀도 재설계

렌트롤 참고 엑셀 4종, 운영 primary API readback, 기업용 데이터 표와 부동산 손익 화면의 공식 가이드를 합쳐 구현 기준을 정리했습니다.

TL;DR

렌트롤

35개 독립 열을 유지하지 않습니다. 면적·보증금·임대료·관리비를 묶어 기본 그리드를 18개 이하로 줄이고, 긴 조건은 같은 행 아래에서 펼칩니다.

수익·비용

원장 중심 화면을 KPI → 추이 → 자산 비교 → NOI 손익표 입력 순으로 바꿉니다. 누락값을 0으로 보간하지 않습니다.

홈

㎡와 평, 임차인·공실·임대면적 요약, 펀드·수익증권·대출을 한 시선 흐름 안에 배치합니다.

사이드바

신규 세 URL에서는 홈·렌트롤·수익비용만 보이고, 기존 URL의 메뉴는 그대로 보존합니다.

근거

출처적용한 원칙
IBM Carbon Data Table표 도구를 한곳에 모으고, 행 확장으로 많은 정보를 점진적으로 노출하며, 고밀도 표에 충분한 폭을 부여합니다.
Material Data Tables숫자 우측 정렬, 명확한 제목, 정렬 상태 표시를 적용합니다.
Power BI dashboard guidance중요 KPI를 먼저 보여주고 일관된 축·색으로 비교합니다.
Power BI small multiples비교 대상이 많아질 때 겹친 선 대신 동일 축의 분할 차트를 사용합니다.
Tableau visual practices색을 줄여 핵심 추세가 다른 요소에 묻히지 않게 합니다.
Oracle Property Manager렌트롤과 임대차 만기 정보를 연결해 검토합니다.

현재 상태와 문제

  • 운영 API는 자산 19개를 반환했고 첫 자산에 렌트롤 14행, 투자 3행, 대출 6행이 확인됐습니다.
  • 참고 엑셀의 공통 열은 약 18개인데 현 렌트롤은 35개 독립 열이라 6,000px를 넘는 가로 폭을 만듭니다.
  • 홈의 투자 원본에서 투입금액을 약정액처럼 표시해 원본 의미가 흐려졌습니다.
  • 수익·비용은 표가 화면을 먼저 차지해 NOI, 추이, 비교 결과를 한눈에 파악하기 어렵습니다.

패턴과 안티패턴

사용

  • 같은 의미의 단위를 한 셀 2줄로 병합
  • 숫자 우측 정렬과 tabular 숫자
  • 계산행과 입력행의 명확한 시각 구분
  • 실제 primary readback만 성공 처리

금지

  • 월별 원장 전체를 첫 화면에 노출
  • 누락값을 임의로 0 처리
  • 한 값을 약정액·투입액에 중복 표시
  • 기존 URL까지 사이드바를 바꾸는 전역 변경

캡처 상태

현재 화면은 기존 라이브 QA 캡처로 확인했고, 외부 공식 사례는 이 실행 환경에서 Lazyweb MCP가 제공되지 않아 페이지 링크와 공개 가이드의 구조를 근거로 사용했습니다. 최종 구현본은 별도의 실제 브라우저 스크린샷으로 비교합니다.

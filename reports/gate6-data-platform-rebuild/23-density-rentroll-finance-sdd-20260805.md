# Gate 6 데이터 플랫폼 정보밀도·렌트롤·NOI 재설계 SDD

작성일: 2026-08-05  
대상 URL: `/data-platform/home`, `/data-platform/rent-roll`, `/data-platform/income-expense`

## 1. 현재 확인 사실

- 운영 API 읽기 확인: 조회 가능 자산 19개, 첫 자산의 렌트롤 14행, 수익증권 투자 3행, 대출 6행이 `status: primary`로 반환된다.
- 운영 원격 catalog는 현재 도구 연결 목록에서 식별되지 않아 직접 SQL catalog 확인으로 가장하지 않는다. API 응답과 저장소 migration을 분리해 근거로 사용한다.
- 참고 렌트롤 4종의 공통 실무 열은 약 18개 안팎이다. 현 화면의 35개 독립 열은 과도하며, 면적·보증금·임대료·관리비를 묶으면 기본 열을 18개 이하로 줄일 수 있다.
- 수익증권 기존 원본의 `투입금액(원)`은 `committed_amount_krw`에 적재되어 있다. API projection에서는 약정액과 투입액을 같은 값으로 복제하지 않고 원본 의미에 맞게 분리한다.

## 2. 화면 계약

### 2.1 좌측 사이드바

- 데이터 플랫폼 URL에서는 `홈`, `렌트롤`, `수익·비용` 세 메뉴만 렌더링한다.
- 기존 물류 URL의 기존 메뉴 구조는 변경하지 않는다.
- 데이터 플랫폼에서는 숨겨진 기능 권한·로그인 이력·일반 알림의 백그라운드 조회도 실행하지 않는다.
- 사용자 프로필과 로그아웃 진입점은 인증 안전을 위해 유지한다.

### 2.2 홈

- 자산 핵심값은 12열 그리드의 고밀도 개요로 배치한다.
- 모든 면적은 `㎡`와 `평`을 함께 표시한다. 환산값은 `㎡ ÷ 3.305785`로 표시만 계산하며 원본은 변경하지 않는다.
- 임차인 현황은 실제 렌트롤 응답에서 고유 임차인 수, 임대 행, 공실 행, 임대면적, 최근 만기를 계산한다.
- 투자 표에는 펀드, 수익자, 약정액, 투입액을 표시하되 실제로 있는 값만 보여준다.
- 대출은 한 표에서 Coupon 금리와 All-in 금리를 함께 유지한다.

### 2.3 렌트롤

- 기본 그리드는 12~18개 열로 제한한다.
- 면적, 보증금, 임대료, 관리비는 한 셀에 원 단위와 평당/평 환산 정보를 2줄로 표시한다.
- 긴 계약 조건은 별도 탭이 아닌 같은 행 바로 아래의 확장 영역에 표시한다.
- 모든 기본 열은 정렬 가능하며, 초기 정렬은 층 내림차순이다.
- 순서·임대 상태·임차인은 좌측에 고정하고, 행 이동은 사용자가 정렬을 해제한 기본 순서에서 수행한다.
- 화면에는 사람 이름을 표시하고 내부 key는 저장 식별에만 사용한다.
- Supabase 응답의 모든 기존 행을 draft state에 보존하며, 숨긴 상세값도 저장 payload에서 제거하지 않는다.

### 2.4 수익·비용

- 정보 순서는 `필터 → KPI → 추이·자산 비교 → NOI 손익표 직접 입력`이다.
- KPI는 잠재총수입, 유효총수입, 운영비용, NOI, NOI 마진을 표시한다.
- 주 차트는 유효총수입·운영비용 막대와 NOI 선을 동일 기간으로 표현하고 X축 라벨을 샘플링한다.
- 자산 비교는 같은 기간·집계·회계 기준을 사용하며 차이와 차이율을 표시한다.
- 직접 입력은 월 집계일 때만 가능하고, 계산행과 입력행을 색·선·레이블로 명확히 구분한다.
- 누락값은 0으로 보간하지 않고 `—`로 표시한다.
- 첨부 이미지의 파란색·노란색 안내 배너, `월별 ... 원장`, `기존 대출 원장` 표현은 사용하지 않는다.

## 3. 데이터 계약

- 홈 임차인 요약은 `v2/rent-roll/read`의 primary 응답만 사용한다.
- 수익증권 금액은 원본 payload의 `약정액`/`투입금액` 의미를 구분해 projection한다. 한 원본 값을 두 열에 중복 표시하지 않는다.
- 렌트롤은 `logistics_core`의 기존 backfill 행을 기본으로 하며, 샘플·fallback·stale 성공을 금지한다.
- 수익·비용은 현재 데이터가 없으므로 담당자가 NOI 손익표에서 입력한 `actual` 값만 저장한다.

## 4. 실패 테스트와 수용 기준

- 데이터 플랫폼 사이드바 DOM에 주 메뉴가 정확히 3개다.
- 홈에 `㎡/평`, 임차인 요약, 약정액·투입액 열이 존재한다.
- 렌트롤 기본 열은 12~18개이며 모든 상세 필드는 같은 페이지에서 접근 가능하다.
- 렌트롤 기존 14행 이상의 primary readback을 화면 state가 그대로 수용한다.
- 수익·비용에 KPI strip, 주 차트, 비교표, NOI 손익표가 모두 존재한다.
- 저장 성공은 서버 재조회 이후에만 표시한다.
- `lint`, frontend contract, DB/API/formula contract, preview build, Edge check, release gate가 통과한다.
- 세 deep link를 새로고침해도 같은 화면이 열리고, 기존 URL에는 회귀가 없다.
